# sigma-alert — Project Instructions

## Git sync
After making code changes, always commit and push to GitHub (`origin master`) before ending the conversation. Also push after completing a significant change or when it has been a while since the last push — don't let unpushed work accumulate. Use descriptive commit messages.

## "Let's finish" workflow
When the user says "let's finish", "we're done", "wrap up", or anything similar that signals the end of a working session, perform this checklist before responding:

1. **Save memory** — write any new feedback, project, user, or reference memories from the session that aren't already captured. Update or remove stale entries.
2. **Update documentation** — refresh `README.md`, `CLAUDE.md`, and any other relevant doc files for the changes made during the session. Don't let docs drift behind the code.
3. **Run tests** — `python -m pytest tests/ -q` must pass before pushing.
4. **Commit and push** — stage relevant files, write a descriptive commit message, push to `origin master`. Include the sibling `Coverage Manager` repo if its files were touched in this session.
5. **Surface anything skipped** — if there are unrelated uncommitted changes, surface them and ask before touching them. Never silently commit or revert work the user didn't explicitly authorize.

## Project structure
- `scripts/sigma_screener.py` — Main screener: data download, distribution math, alert tier logic, Slack formatting
- `scripts/sync_watchlist.py` — Merges `sources/*.txt` into `watchlist.txt` (does NOT touch `ticker_metadata.json`)
- `scripts/refresh_sp500.py` — Quarterly S&P 500 reconstitution refresh from Wikipedia. Writes BOTH `sources/sp500.txt` (ticker list) and `sources/sp500_names.json` (ticker→company name map, used by the screener as a name fallback)
- `scripts/weekly_skip_report.py` — Reads `cache/skip_log.json` and posts a trailing-7-day skip digest to the `#status-reports` Slack channel every Friday. Standalone — does not require Coverage Manager
- `scripts/local_run.ps1` — Per-run worker for the optional **local backstop**. Read-only consumer: refreshes the disposable runner clone to `origin/master`, runs one screener mode, posts to Slack, exits. Never commits or pushes. Invoked by the Windows Scheduled Tasks registered by `setup_local_runner.ps1`. Reads `SLACK_WEBHOOK` (and optional `PYTHON_EXE`) from a gitignored `.env` in the runner clone
- `scripts/setup_local_runner.ps1` — One-time idempotent bootstrap for the local backstop: clones sigma-alert to `%LOCALAPPDATA%\sigma-alert-runner` (outside Dropbox), installs deps, writes `.env`, and registers three weekday Scheduled Tasks (`SigmaAlert-open` 09:40, `-midday` 12:35, `-close` 16:25, machine-time/ET) with `StartWhenAvailable` + battery-friendly settings. **No dedup with GitHub Actions** — duplicate alerts are accepted by design (user explicitly opted out of coordination; only requirement is each event fires within ~30 min). Both `.ps1` files are kept ASCII-only per the PowerShell-5.1 codepage gotcha
- `sources/` — Per-segment ticker lists (hc_services, medtech, sp500, index_etfs, sector_etfs, healthcare_etfs) plus name-fallback JSONs
- `sources/sp500_names.json` — `{TICKER: "Company Name"}` from Wikipedia, used at startup to fill name gaps for S&P 500 tickers that Coverage Manager doesn't maintain (CM covers Healthcare Services, MedTech, Biopharma, plus a curated Tech/SaaS/Fintech/Other slice). Regenerated by `refresh_sp500.py` on every run (even when ticker set is unchanged, to catch renames like Facebook→Meta)
- `sources/index_etfs.txt` — Broad-market index ETFs (SPYM, DIA, QQQ). Render at the top of the **Index & Sector Returns** Slack section
- `sources/sector_etfs.txt` — SPDR Select Sector ETFs (XLE, XLF, XLV, etc.). Render below the indices in the same section
- `sources/healthcare_etfs.txt` — Healthcare sub-sector ETFs (XBI, IBB, IHI, XHS, PPH, IHE) plus the `^DRG` NYSE Arca Pharmaceutical **index** (a caret index ticker, not an ETF — added 2026-05-31 for a price-return pharma benchmark alongside the funds). Render below the SPDR sectors under a `_Healthcare_` sub-header in the same section. `^DRG` survives the yfinance batch download + MultiIndex extraction and inherits the `etf_set` exemptions (missing-metadata flag + alert suppression) like any other returns-block ticker
- `sources/etf_names.json` — `{TICKER: friendly name}` for index, sector, and healthcare ETFs (Coverage Manager doesn't track ETFs, so display names live here). Authoritatively overrides metadata for ETF tickers at startup (name replaced, sector/subsector cleared) — unlike `sp500_names.json`, which only fills blanks. The override is required because ETF tickers can collide with foreign equities in CM's universe (e.g. `DIA` is both the SPDR DJIA ETF and DiaSorin S.p.A. on Borsa Italiana); without the override, ETFs would display the wrong name and could be mis-tagged into a 1σ alert sector
- `watchlist.txt` — Combined deduped ticker list, generated by sync_watchlist.py
- `ticker_metadata.json` — `{TICKER: {name, sector, subsector}}` lookup, **owned by Coverage Manager** (written via its weekly-build sigma-export step). Do NOT regenerate it from CI — the runner has no access to the Coverage Manager CSV. The screener deep-copies this dict at startup and merges `sp500_names.json` into the copy for display purposes; the original is kept intact for `write_missing_metadata_flag` so CM still sees true gaps
- `core_watchlist.json` — DEPRECATED back-compat file (legacy union of Portfolio + Researching). Pushed by Coverage Manager for one cycle while the screener migrates fully off it. The screener loads it only as a fallback when `portfolio.json`/`researching.json` are absent (e.g. fresh clone). Will stop being pushed once the screener stops loading it
- `portfolio.json`, `researching.json`, `following_for_interest.json`, `ready_to_buy.json`, `ready_to_short.json` — `{TICKER: {position, buy_price, sell_price, position_date, ..., name, sector, subsector, core}}`, **owned by Coverage Manager** (pushed in the same commit as `ticker_metadata.json`). One file per Coverage Manager `Position` value. The screener loads each into a ticker set, uses them in the 1σ eligibility gate, and renders matching alerts under their corresponding subcategory header. Missing files are not fatal — the corresponding subcategory just renders empty
- `cache/distribution_cache.json` — Per-ticker `{mu, sigma, sample_size, high_52w, low_52w}` from EOD run, used by morning open run to skip full history download. `high_52w`/`low_52w` cached so the cached-open path can render the 52w range; existing entries missing these fields degrade gracefully until the next close run refreshes the cache
- `cache/missing_metadata.json` — Written by EOD run when watchlist tickers are missing from `ticker_metadata.json` (or have a blank name). Coverage Manager's weekly `sigma_export` reads this from the sibling clone and surfaces the gaps. File is deleted automatically when there are no gaps. Committed by `sigma-close.yml` alongside the distribution cache. Index/sector ETFs are exempt from this check — their names live in `sources/etf_names.json` rather than CM's universe, so flagging them as gaps would be a false positive
- `cache/skip_log.json` — Per-run skip events written by EOD close runs, trimmed to a trailing 30-day window. Schema: `{"runs": [{"date", "mode", "skipped": [{"ticker", "reason"}]}]}`. Reasons emitted: `insufficient_history`, `distribution_nan`, `fallback_insufficient`, `fallback_exception`. Consumed by `scripts/weekly_skip_report.py` for the Friday digest. Committed by `sigma-close.yml`
- `.github/workflows/` — sigma-open, sigma-midday, sigma-close (cron-fired), sync-watchlist, sigma-watchdog (recovers dropped runs), sigma-weekly-skip-report (Friday 22:30 UTC, posts skip digest to `#status-reports`)
- `tests/` — pytest suite

## Sibling projects
- `../Coverage Manager/` — Owns `ticker_metadata.json`. Its weekly-build pipeline writes the file directly into this clone via `reporting/sigma_export.py` and pushes only that single file.

## Key conventions
- All time logic uses `America/New_York` (ET) via `zoneinfo.ZoneInfo`
- yfinance `auto_adjust=True` is used so Close prices reflect splits/dividends
- z-score formula: `z = (today_return - μ) / σ`, where μ/σ come from trailing 252 daily returns
- Alert tiers in Slack output:
  - **2σ+ Moves** — fires on the entire watchlist when `|z| ≥ 2.0`. 3σ+ moves get an inline warning emoji
  - **1σ Moves** — fires only on names you care about analytically. Eligibility is `Core == "Y"` in Coverage Manager metadata (read from `ticker_metadata.json` schema v3+), OR membership in any of the five Position lists pushed by Coverage Manager (Portfolio, Researching, Following for Interest, Ready to Buy, Ready to Short). See `_is_one_sigma_eligible()` in `scripts/sigma_screener.py`. Expanded from {Portfolio, Researching} to all five lists on 2026-05-11 when Coverage Manager's Position taxonomy expanded.
- Within each tier, alerts are grouped into subcategories in fixed order:
  **Portfolio → Researching → Ready to Buy → Ready to Short → Following for Interest → Healthcare Services → MedTech → Large Pharma → Other (Tech/SaaS/Fin/Ind/Cons/Energy/Mat/RE) → S&P 500** (driven by the `SUBCATEGORIES` list in `sigma_screener.py`).
  - The five Position-derived buckets (Portfolio, Researching, Ready to Buy, Ready to Short, Following for Interest) come from Coverage Manager's per-state JSON files: `portfolio.json`, `researching.json`, `ready_to_buy.json`, `ready_to_short.json`, `following_for_interest.json`. Order reflects closeness-to-action: held → thesis-building → trigger-ready → passive-tracking.
  - "Large Pharma" matches `subsector == "Large Pharma"` (~26 names: PFE, MRK, LLY, NVO, ABBV, BMY, etc.).
  - "Other (Tech, SaaS, Fin, Ind, Cons, Energy, Mat, RE)" matches `sector ∈ SECTORS_GROUPED_AS_OTHER` — the seven sectors that absorbed the legacy "Other" / "PA" catch-all on 2026-05-03 plus Tech and SaaS.
  - A ticker matching multiple categories is rendered once per category — intentional duplication.
  - 2σ alerts outside all buckets (e.g. a non-Core mid-cap Biotech not in S&P 500) are **dropped** rather than shown in an "Other" catch-all.
  - S&P 500 membership comes from `sources/sp500.txt` via `load_sp500_set()` — a static list maintained in this repo, not from Coverage Manager, updated manually after quarterly reconstitutions
- Alerts within each tier sorted by signed z-score descending (biggest gainers top, biggest losers bottom)
- Alert lines render as `` 🟩/🟥 `TICKER` (Short name) | +Y.YY% | z = +X.XX | $PRICE | P% of 52w high | 52w: $LOW - $HIGH `` — % change comes before z-score. Tickers are rendered as backtick-monospace chips (unified 2026-05-27 across all sigma surfaces — alert lines, 52w hi/lo list, ETF rows, weekly skip report). Sector is implied by the subcategory header, not repeated per line. 52-week hi/lo lines (the new-high/new-low list in the close digest) still carry `[Sector]` inline. `P% of 52w high` (added 2026-05-27) is rendered between the price and the 52w range whenever both `price` and `high_52w` are available; it gives a fast read of how stretched the current quote is vs. its trailing-year ceiling. Short name via `short_company_name()` (which strips both space-separated and glued suffixes like `AptarGroup` → `Aptar`). Names for S&P 500 tickers not in Coverage Manager's metadata come from `sources/sp500_names.json` (Wikipedia fallback)
- Below the alert tiers, every Slack message renders an **Index & Sector Returns** section. Indices (SPYM/DIA/QQQ from `sources/index_etfs.txt`) appear first under an `_Indices_` sub-header sorted by z-score, then SPDR sector ETFs (`sources/sector_etfs.txt`) under `_Sectors_`, then healthcare sub-sector ETFs + the `^DRG` pharma index (XBI/IBB/IHI/XHS/PPH/IHE/^DRG from `sources/healthcare_etfs.txt`) under `_Healthcare_`, all sorted by z-score within their group. The screener unions all three ETF sets into the download list at startup so the section still renders even if a watchlist sync (Coverage Manager's, in particular) drops the ETFs from `watchlist.txt`. Data reuses the same `_process_ticker_full` output that drives alerts — no extra downloads for the today/z-score columns. Each ETF row also carries **prior calendar year** and **YTD** returns appended as `| 2025: ±X.XX% | YTD: ±X.XX%`. These come from a separate, dedicated longer-window fetch (`fetch_etf_period_returns()` — ~800 calendar days, ETF-only) so the main 400-day batch download stays small; the side fetch covers only ~19 tickers. Rows where the prior-prior year-end close can't be located (e.g. ETF inception after the relevant cutover) render without the period suffix rather than failing
- Cron schedules use EST-aligned UTC offsets so they always fire after the relevant market event year-round (1 hour late during EDT, but never early)
- `Sigma Watchdog` workflow runs hourly during weekday market hours, detects dropped scheduled runs, and triggers them via `workflow_dispatch`. Posts a Slack heartbeat only when it actually recovers something
- Slack webhooks — stored as GitHub Actions secrets:
  - `SLACK_WEBHOOK` — main sigma-alert channel (`#stock-price-alerts`). Used by the sigma screener for open/midday/close digests
  - `SLACK_STATUS_REPORTS_WEBHOOK` — `#status-reports` channel. Used only by `scripts/weekly_skip_report.py`
