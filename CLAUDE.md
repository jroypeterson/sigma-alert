# sigma-alert — Project Instructions

## Git sync
After making code changes, always commit and push to GitHub (`origin master`) before ending the conversation. Also push after completing a significant change or when it has been a while since the last push — don't let unpushed work accumulate. Use descriptive commit messages.

## "Let's finish" workflow
When the user says "let's finish", "we're done", "wrap up", or anything similar that signals the end of a working session, perform this checklist before responding:

1. **Save memory** — write any new feedback, project, user, or reference memories from the session that aren't already captured. Update or remove stale entries.
2. **Update documentation** — refresh `README.md`, `CLAUDE.md`, and any other relevant doc files for the changes made during the session. Don't let docs drift behind the code.
3. **Run tests** — `python -m pytest tests/ -q` must pass before pushing.
4. **Commit and push** — stage relevant files, write a descriptive commit message, push to `origin master`. Include the sibling `Coverage Manager` repo if its files were touched in this session.
5. **Surface anything skipped** — if there are unrelated uncommitted changes, surface them and ask before touching them. Never silently commit or revert work the user didn't explicitly authorize.

## Project structure
- `scripts/sigma_screener.py` — Main screener: data download, distribution math, alert tier logic, Slack formatting
- `scripts/sync_watchlist.py` — Merges `sources/*.txt` into `watchlist.txt` (does NOT touch `ticker_metadata.json`)
- `scripts/refresh_sp500.py` — Quarterly S&P 500 reconstitution refresh from Wikipedia. Writes BOTH `sources/sp500.txt` (ticker list) and `sources/sp500_names.json` (ticker→company name map, used by the screener as a name fallback)
- `scripts/weekly_skip_report.py` — Reads `cache/skip_log.json` and posts a trailing-7-day skip digest to the `#status-reports` Slack channel every Friday. Standalone — does not require Coverage Manager. Honors `sources/skip_report_suppress.txt`: tickers there are held out of the **Chronic skips** and **Unresolved** sections (genuinely-new listings still accreting <32 bars), but are still counted and surfaced under a compact `Suppressed` line so the suppression is never silent. Entries support `until=YYYY-MM-DD` so a new IPO that still can't price after it should have crossed 32 bars re-surfaces as a real flag. **Prefer fixing a wrong/foreign symbol via `_YF_SYMBOL_OVERRIDES` over suppressing it** — suppress only correct-but-too-young names
- `scripts/post_overview.py` — Builds and (with `--post`) sends the pinned reference card for `#stock-price-alerts` (the "what am I looking at" overview). **Generated from the live source files** (group lists + `etf_names.json`) so it never drifts; default is a dry-run print, `--post` sends via `SLACK_WEBHOOK`. Webhooks can't pin — pin by hand after it lands. Re-run + re-pin after any structural change (per the "Slack channels need a pinned overview" convention)
- `scripts/return_map.py` — Builds the interactive **return-map** (`readable/return_map.html`), a BlackRock-style periodic-table-of-returns for the index/asset groups the returns block already tracks. **Reuses the screener's existing returns computation — no extra market-data fetch:** the screener writes `cache/returns_snapshot.json` at the end of every run (the index/sector/macro returns block packed to JSON, warn-and-proceed so it never breaks the alert pipeline) and `return_map.build_html()` renders three ranked, color-by-asset-class columns (Prior Year / YTD / Today). Self-contained HTML (no CDN/libs, works offline off disk). Manual entry point: `python scripts/return_map.py` (rebuilds from the committed snapshot, no APIs), `--sample` (bundled demo data), `--open` (open in browser). The snapshot is committed by `sigma-close.yml`; the rendered HTML is a derived runtime artifact (`readable/` is gitignored). Excludes yield-style macro rows (e.g. `^TNX`) — a % return on a yield level isn't return-comparable
- `scripts/local_run.ps1` — Per-run worker for the optional **local backstop**. Read-only consumer: refreshes the disposable runner clone to `origin/master`, runs one screener mode, posts to Slack, exits. Never commits or pushes. Invoked by the Windows Scheduled Tasks registered by `setup_local_runner.ps1`. Reads `SLACK_WEBHOOK` (and optional `PYTHON_EXE`) from a gitignored `.env` in the runner clone
- `scripts/setup_local_runner.ps1` — One-time idempotent bootstrap for the local backstop: clones sigma-alert to `%LOCALAPPDATA%\sigma-alert-runner` (outside Dropbox), installs deps, writes `.env`, and registers three weekday Scheduled Tasks (`SigmaAlert-open` 09:40, `-midday` 12:35, `-close` 16:25, machine-time/ET) with `StartWhenAvailable` + battery-friendly settings. **No dedup with GitHub Actions** — duplicate alerts are accepted by design (user explicitly opted out of coordination; only requirement is each event fires within ~30 min). Both `.ps1` files are kept ASCII-only per the PowerShell-5.1 codepage gotcha
- `sources/` — Per-segment ticker lists (hc_services, medtech, sp500, index_etfs, sector_etfs, healthcare_etfs, tech_etfs, macro) plus name-fallback JSONs
- `sources/sp500_names.json` — `{TICKER: "Company Name"}` from Wikipedia, used at startup to fill name gaps for S&P 500 tickers that Coverage Manager doesn't maintain (CM covers Healthcare Services, MedTech, Biopharma, plus a curated Tech/SaaS/Fintech/Other slice). Regenerated by `refresh_sp500.py` on every run (even when ticker set is unchanged, to catch renames like Facebook→Meta)
- `sources/index_etfs.txt` — Broad-market index benchmarks (SPYM, DIA, QQQ, the `^W5000` Wilshire 5000 whole-market index, and the `^RUT` Russell 2000 small-cap index — caret index tickers like `^DRG`, added 2026-06-02 / 2026-06-21). Render under `_US Indices_` (renamed from `_Indices_` on 2026-06-29 per #20), which **leads** the **Index, Sector & Macro Returns** Slack section (US index price returns are the headline; the macro/rates/credit backdrop follows)
- `sources/global_equity_etfs.txt` — Global/international equity index ETFs (`ACWI` MSCI ACWI, `EFA` developed ex-US, `EEM` EM, `VGK` developed Europe, `EWJ`/`EWY`/`FXI`/`INDA` Japan/Korea/China/India; added 2026-06-03). Render under `_Global Equity_` below the US `_US Indices_` group via the normal `_format_etf_line()` with prior-year/YTD returns; `etf_names.json` carries the geography name. The country ETFs are USD-denominated, so each bundles the local-equity move AND the FX move vs the dollar (the `_Macro_` DXY row is the dollar backdrop)
- `sources/tech_etfs.txt` — Tech-theme ETFs (`MAGS` Mag-7, `SMH`/`SOXX` semis, `IGV` software, `DTCR` data-center REITs, `AIQ` AI/tech; added 2026-06-02). Regular total-return ETFs — render under `_Tech Themes_` (below `_Healthcare_`) via the normal `_format_etf_line()` with prior-year/YTD returns; `etf_names.json` carries representative holdings in the parenthetical (e.g. `Semis: NVDA, TSM, AVGO`). Decided in a scope discussion: a standalone "AI" bucket was rejected (it's a fuzzy theme — AIQ itself is semis-heavy), expressed via Semis + Mag-7 instead
- `sources/commodity_etfs.txt` — Commodity ETFs (`GLD` Gold; added 2026-06-03 for the "gold index price return" request). Regular total-return ETFs — render under `_Commodities_` (below `_Tech Themes_`) via the normal `_format_etf_line()` with prior-year/YTD returns; `etf_names.json` carries the friendly name (`GLD`="Gold")
- **Credit indices (HY/IG) — NOT a source file.** Sourced live from FRED's public no-key CSV endpoint (`fredgraph.csv`), defined in the `CREDIT_SERIES`/`CREDIT_ORDER` constants in `sigma_screener.py`. Four ICE BofA series: HY effective yield (`BAMLH0A0HYM2EY`) + OAS (`BAMLH0A0HYM2`), IG effective yield (`BAMLC0A0CMEY`) + OAS (`BAMLC0A0CM`). Fetched by `fetch_credit_indices()` (bounded to a ~2-year `cosd` window so the multi-decade CSV doesn't time out; one retry; warn-and-proceed on failure → the `_Credit_` block is simply omitted). Render under `_Credit_` (after `_Macro_`) via `_format_credit_line()`: each row shows effective-yield level + day basis-point change, OAS level + day bp change, and a trailing **`YTD: yield ±bp, OAS ±bp`** segment carrying BOTH year-to-date moves in absolute bp, each labeled (a single unlabeled "YTD" is ambiguous when both a yield and a spread are shown; a % "return" on a yield/spread is misleading). Colored by the OAS move (widening = risk-off = 🟥, tightening = 🟩; falls back to the yield change when OAS is unavailable). These are levels, not tradeable tickers — no z-score, no alert, not in the yfinance download path. **No API key / GH secret required** (FRED CSV is public)
- **US Treasury yield curve (2/10/30) — NOT a source file.** Also sourced live from FRED's public no-key CSV, defined in the `TREASURY_CURVE_SERIES`/`TREASURY_CURVE_ORDER` constants. Three daily constant-maturity series: `DGS2`/`DGS10`/`DGS30`. Yahoo/yfinance has **no 2-year** yield ticker (only `^FVX`/`^TNX`/`^TYX`), so the full 2/10/30 curve must come from FRED — whose daily yields publish the **prior business day's close** next morning, i.e. exactly "yesterday's close". Fetched by `fetch_treasury_curve()` (same ~2-year `cosd` bound + warn-and-proceed as credit → an empty dict omits the `_Treasury Curve_` block). Render under `_Treasury Curve_` (**after `_Macro_`, before `_Credit_`**) via `_format_curve_line()`: each maturity shows `level% | ±bp (1-day move) | YTD: ±bp (from prior year-end)`, in fixed 2Y→10Y→30Y order. **Colored like a bond, NOT an equity:** a yield RISE = price decline = 🟥, a yield FALL = 🟩 (same inversion `_format_credit_line` applies to OAS). This is deliberately SEPARATE from the intraday `^TNX` 10Y in `_Macro_` — that row is a live (today) tick, this curve is the prior-close snapshot across maturities, so the 10Y intentionally appears in both. Levels, not tickers — no z-score, no alert, not in the yfinance path. **No API key / GH secret required** (FRED CSV is public)
- `sources/macro.txt` — Cross-asset macro tickers (`^TNX` 10Y Treasury yield, `DX-Y.NYB` US Dollar Index, `CL=F` WTI crude; added 2026-06-02). NOT ETFs, but unioned into `etf_set` so they share the download path + alert/missing-metadata exemptions. Render under `_Macro_` at the **top** of the returns section via the dedicated `_format_macro_line()` (a bond yield is a level, not a price — see the `MACRO_STYLE`/`MACRO_ORDER` constants). Included in the period-returns fetch for their YTD figure: WTI/dollar index as a YTD % return; the 10Y yield as a YTD basis-point move from its year-start level (a YTD % "return" on a yield is misleading, so the level + bp move is shown instead)
- `sources/sector_etfs.txt` — SPDR Select Sector ETFs (XLE, XLF, XLV, etc.). Render below the indices in the same section
- `sources/healthcare_etfs.txt` — Healthcare sub-sector ETFs (XBI, IBB, IHI, XHS, PPH, IHE) plus the `^DRG` NYSE Arca Pharmaceutical **index** (a caret index ticker, not an ETF — added 2026-05-31 for a price-return pharma benchmark alongside the funds). Render below the SPDR sectors under a `_Healthcare_` sub-header in the same section. `^DRG` survives the yfinance batch download + MultiIndex extraction and inherits the `etf_set` exemptions (missing-metadata flag + alert suppression) like any other returns-block ticker
- `sources/etf_names.json` — `{TICKER: friendly name}` for index, sector, healthcare, and macro tickers (Coverage Manager doesn't track these, so display names live here). The three pharma rows are labeled by **composition** so they're distinguishable at a glance: `PPH`="Pharma (25 large-cap)", `IHE`="Pharma (US diversified)", `^DRG`="Pharma (large-cap index)" (relabeled 2026-06-02 from provider-based names). Authoritatively overrides metadata for ETF tickers at startup (name replaced, sector/subsector cleared) — unlike `sp500_names.json`, which only fills blanks. The override is required because ETF tickers can collide with foreign equities in CM's universe (e.g. `DIA` is both the SPDR DJIA ETF and DiaSorin S.p.A. on Borsa Italiana); without the override, ETFs would display the wrong name and could be mis-tagged into a 1σ alert sector
- `watchlist.txt` — Combined deduped ticker list, generated by sync_watchlist.py
- `ticker_metadata.json` — `{TICKER: {name, sector, subsector}}` lookup, **owned by Coverage Manager** (written via its weekly-build sigma-export step). Do NOT regenerate it from CI — the runner has no access to the Coverage Manager CSV. The screener deep-copies this dict at startup and merges `sp500_names.json` into the copy for display purposes; the original is kept intact for `write_missing_metadata_flag` so CM still sees true gaps
- `core_watchlist.json` — DEPRECATED back-compat file (legacy union of Portfolio + Researching). Pushed by Coverage Manager for one cycle while the screener migrates fully off it. The screener loads it only as a fallback when `portfolio.json`/`researching.json` are absent (e.g. fresh clone). Will stop being pushed once the screener stops loading it
- `portfolio.json`, `researching.json`, `following_for_interest.json`, `ready_to_buy.json`, `ready_to_short.json` — `{TICKER: {position, buy_price, sell_price, position_date, ..., name, sector, subsector, core}}`, **owned by Coverage Manager** (pushed in the same commit as `ticker_metadata.json`). One file per Coverage Manager `Position` value. The screener loads each into a ticker set, uses them in the 1σ eligibility gate, and renders matching alerts under their corresponding subcategory header. Missing files are not fatal — the corresponding subcategory just renders empty
- `cache/distribution_cache.json` — Per-ticker `{mu, sigma, sample_size, high_52w, low_52w, prior_year_end_close, prior_year_end_year}` from EOD run, used by morning open run to skip full history download. `high_52w`/`low_52w` cached so the cached-open path can render the 52w range; `prior_year_end_close`/`prior_year_end_year` cached so the cached-open path can compute YTD (the year guards against the year-boundary edge case). Existing entries missing any of these fields degrade gracefully until the next close run refreshes the cache
- `cache/missing_metadata.json` — Written by EOD run when watchlist tickers are missing from `ticker_metadata.json` (or have a blank name). Coverage Manager's weekly `sigma_export` reads this from the sibling clone and surfaces the gaps. File is deleted automatically when there are no gaps. Committed by `sigma-close.yml` alongside the distribution cache. Index/sector ETFs are exempt from this check — their names live in `sources/etf_names.json` rather than CM's universe, so flagging them as gaps would be a false positive
- `cache/skip_log.json` — Per-run skip events written by EOD close runs, trimmed to a trailing 30-day window. Schema: `{"runs": [{"date", "mode", "skipped": [{"ticker", "reason"}]}]}`. Reasons emitted: `insufficient_history`, `distribution_nan`, `fallback_insufficient`, `fallback_exception`. Consumed by `scripts/weekly_skip_report.py` for the Friday digest. Committed by `sigma-close.yml`
- `.github/workflows/` — sigma-open, sigma-midday, sigma-close (cron-fired), sync-watchlist, sigma-watchdog (recovers dropped runs), sigma-weekly-skip-report (Friday 22:30 UTC, posts skip digest to `#status-reports`)
- `tests/` — pytest suite

## Key conventions
- **Foreign-ticker symbol normalization (2026-06-13).** Coverage Manager pushes foreign coverage names as Bloomberg-style symbols (`GETIB.SS`, `COH.AU`, …) and keys `ticker_metadata.json` + the position JSONs by the **bare base symbol** (`GETIB`, `COH`; zero dotted keys). yfinance needs a third form (`GETI-B.ST`, `COH.AX`). So a foreign watchlist ticker carries three identities: **display** (watchlist ticker — Slack label, cache key, skip-log key), **yf symbol** (`to_yf_symbol`), and **meta key** (the base symbol CM joins on — `to_metadata_key`). `to_yf_symbol` applies an explicit `_YF_SYMBOL_OVERRIDES` map (class shares like GETIB→GETI-B + bare foreign names like FRE→FRE.DE, all verified live against yfinance) then a Bloomberg→yfinance suffix remap (`_BLOOMBERG_SUFFIX_MAP`: SS→ST, AU→AX, IM→MI, DC→CO, LN→L, FP→PA, CH→SW, GY→DE); suffixes already in yfinance form (.DE/.MI/.SW/.L/.SA/.T/.HK) pass through. `to_metadata_key` strips any recognized exchange suffix to the base. US tickers, dash-form US class shares (BF-B, BRK-B), and caret indices (^TNX) are unchanged by both — a *dotted* ticker is always a foreign listing, so there's no US-class-share collision. Threaded through `screen_full` (download/slice by yf symbol, `meta_key=` into `_process_ticker_full`), `screen_open_cached`/`download_todays_prices`, `fetch_etf_period_returns` (download yf, key results by display), and `write_missing_metadata_flag` (join by base so foreign names stop false-flagging). Fixed the chronic `insufficient_history (<32 bars)` skips for the ~24 suffixed + 8 bare foreign names. Two more added 2026-06-21: `CVSG`→`CVSG.L` (CVS Group plc, LSE) and `SFZS.SW`→`SFZN.SW` (Siegfried Holding — CM's "SFZS" was a typo, the real SIX symbol is SFZN). **CM corrected at source 2026-06-23** (CVSG→CVSG.L; the duplicate SFZS/SFZN rows merged to a single `SFZN.SW`), so once that propagates via the next CM weekly-build these two overrides become dead bridges and can be removed. **Residual:** `MMED` left untouched (ambiguous — "MMED" on Nasdaq ≠ CM's metadata name); add to `_YF_SYMBOL_OVERRIDES` once resolved.
- All time logic uses `America/New_York` (ET) via `zoneinfo.ZoneInfo`
- yfinance `auto_adjust=True` is used so Close prices reflect splits/dividends
- z-score formula: `z = (today_return - μ) / σ`, where μ/σ come from trailing 252 daily returns
- Alert tiers in Slack output:
  - **2σ+ Moves** — fires on the entire watchlist when `|z| ≥ 2.0`. 3σ+ moves get an inline warning emoji
  - **1σ Moves** — fires only on names you care about analytically. Eligibility is `Core == "Y"` in Coverage Manager metadata (read from `ticker_metadata.json` schema v3+), OR membership in any of the five Position lists pushed by Coverage Manager (Portfolio, Researching, Following for Interest, Ready to Buy, Ready to Short). See `_is_one_sigma_eligible()` in `scripts/sigma_screener.py`. Expanded from {Portfolio, Researching} to all five lists on 2026-05-11 when Coverage Manager's Position taxonomy expanded.
- Within each tier, alerts are grouped into subcategories in fixed order:
  **Portfolio → Researching → Ready to Buy → Ready to Short → Following for Interest → Healthcare Services → MedTech → Large Pharma → Other (Tech/SaaS/Fin/Ind/Cons/Energy/Mat/RE) → S&P 500** (driven by the `SUBCATEGORIES` list in `sigma_screener.py`).
  - The five Position-derived buckets (Portfolio, Researching, Ready to Buy, Ready to Short, Following for Interest) come from Coverage Manager's per-state JSON files: `portfolio.json`, `researching.json`, `ready_to_buy.json`, `ready_to_short.json`, `following_for_interest.json`. Order reflects closeness-to-action: held → thesis-building → trigger-ready → passive-tracking.
  - "Large Pharma" matches `subsector == "Large Pharma"` (~26 names: PFE, MRK, LLY, NVO, ABBV, BMY, etc.).
  - "Other (Tech, SaaS, Fin, Ind, Cons, Energy, Mat, RE)" matches `sector ∈ SECTORS_GROUPED_AS_OTHER` — the seven sectors that absorbed the legacy "Other" / "PA" catch-all on 2026-05-03 plus Tech and SaaS.
  - A ticker matching multiple categories is rendered once per category — intentional duplication.
  - 2σ alerts outside all buckets (e.g. a non-Core mid-cap Biotech not in S&P 500) are **dropped** rather than shown in an "Other" catch-all.
  - S&P 500 membership comes from `sources/sp500.txt` via `load_sp500_set()` — a static list maintained in this repo, not from Coverage Manager, updated manually after quarterly reconstitutions
- Alerts within each tier sorted by signed z-score descending (biggest gainers top, biggest losers bottom)
- Alert lines render as `` 🟩/🟥 `TICKER` (Short name) | +Y.YY% | z = +X.XX | $PRICE | P% of 52w high | 52w: $LOW - $HIGH | 2025: ±W.WW% | YTD: ±Z.ZZ% `` — % change comes before z-score. The trailing `2025: ±% | YTD: ±%` pair (added 2026-06-02) mirrors the ETF/returns-block rows. **YTD** (year-to-date return vs the prior calendar year-end close): comes from the in-memory close history in the full-screen path (close/midday/full-open — the 400-day window always reaches it, so **no extra download**); in the morning cached-open path it's read from `prior_year_end_close` in `distribution_cache.json` (written by the prior EOD close run), guarded by a stored `prior_year_end_year` so a stale December cache used on the first session of a new year omits YTD rather than computing it off the wrong baseline; falls back to the period fetch's YTD when the cache lacks the field. **Prior calendar-year return** (`2025: ±%`): needs the year-before-last's (2024) year-end close, which is older than the 400-day screen window, so the alert tickers are folded into the dedicated ~800-day `fetch_etf_period_returns()` call alongside the ETFs (one batched download). The column always renders on alert rows: when the baseline can't be located (e.g. an IPO after that cutover) it shows `2025: N/A` rather than being dropped. (YTD is still dropped if its own baseline is unavailable.) Tickers are rendered as backtick-monospace chips (unified 2026-05-27 across all sigma surfaces — alert lines, 52w hi/lo list, ETF rows, weekly skip report). Sector is implied by the subcategory header, not repeated per line. The 52-week hi/lo list (new highs/lows in the close digest) is **grouped by the same subcategory taxonomy as the alert tiers** (Portfolio → … → MedTech → HC Services → S&P 500), each name rendered as a compact chip carrying `[Sector]` inline, with an `Uncategorized` catch-all so names outside every bucket are surfaced rather than dropped (added 2026-06-03; unlike the alert tiers, which drop unmatched names). A name in multiple buckets shows once per bucket. The section is chunked across blocks if it exceeds Slack's 3000-char limit. `P% of 52w high` (added 2026-05-27) is rendered between the price and the 52w range whenever both `price` and `high_52w` are available; it gives a fast read of how stretched the current quote is vs. its trailing-year ceiling. Short name via `short_company_name()` (which strips both space-separated and glued suffixes like `AptarGroup` → `Aptar`). Names for S&P 500 tickers not in Coverage Manager's metadata come from `sources/sp500_names.json` (Wikipedia fallback)
- Below the alert tiers, every Slack message renders an **Index, Sector & Macro Returns** section. A `_US Indices_` sub-header **leads** (broad-market read — SPYM/DIA/QQQ/`^W5000`/`^RUT` from `sources/index_etfs.txt`, sorted by z-score; renamed from `_Indices_` and moved to the top on 2026-06-29 per #20 so US index price returns are the headline). Then a `_Macro_` sub-header (cross-asset backdrop: `^TNX`/`DX-Y.NYB`/`CL=F` from `sources/macro.txt`, rendered in fixed `MACRO_ORDER` — rates → FX → commodity — *not* z-sorted, since three unlike asset classes don't sort meaningfully). The 10Y yield renders as `level% | ±bp | z | YTD: ±Xbp from Y.YY%` (it's a yield, not a price, so YTD is shown as a basis-point move off the year-start level rather than a % return) and is **colored like a bond — a yield rise is 🟥 (price down), a fall is 🟩** (the `yield` style inverts the marker in `_format_macro_line`; the `price`/`level` styles for oil/dollar keep normal green-on-up); the dollar index as `level | ±% | z | YTD: ±%`; oil as `$price | ±% | z | YTD: ±%`. Then a `_Treasury Curve_` sub-header (US 2/10/30 from FRED `DGS2/10/30` — see the Treasury-curve note above; prior-close `level% | ±bp | YTD: ±bp`, fixed 2Y→10Y→30Y order, colored bond-style). Then a `_Credit_` sub-header (HY/IG effective yields + OAS spreads from FRED — see the credit-indices note above; `yield X.XX% ±bp | OAS Zbp ±bp | YTD ±bp`, fixed HY→IG order, colored by the spread move). Then global/international equity index ETFs (ACWI/EFA/EEM/VGK/EWJ/EWY/FXI/INDA from `sources/global_equity_etfs.txt`) under `_Global Equity_`, then SPDR sector ETFs (`sources/sector_etfs.txt`) under `_Sectors_`, then healthcare sub-sector ETFs + the `^DRG` pharma index (XBI/IBB/IHI/XHS/PPH/IHE/^DRG from `sources/healthcare_etfs.txt`) under `_Healthcare_`, then tech-theme ETFs (MAGS/SMH/SOXX/IGV/DTCR/AIQ from `sources/tech_etfs.txt`) under `_Tech Themes_`, then commodity ETFs (`GLD` from `sources/commodity_etfs.txt`) under `_Commodities_`, all sorted by z-score within their group. The screener unions all the index/sector/healthcare/tech/macro sets into the download list at startup so the section still renders even if a watchlist sync (Coverage Manager's, in particular) drops the ETFs from `watchlist.txt`. Data reuses the same `_process_ticker_full` output that drives alerts — no extra downloads for the today/z-score columns. Each **ETF** row also carries **prior calendar year** and **YTD** returns appended as `| 2025: ±X.XX% | YTD: ±X.XX%`. These come from a separate, dedicated longer-window fetch (`fetch_etf_period_returns()` — ~800 calendar days) so the main 400-day batch download stays small; the side fetch covers the index/sector/healthcare/tech ETFs, the alert tickers, AND the macro tickers. Macro rows also carry a YTD figure from this fetch: WTI/dollar-index as a YTD % return, and the 10Y yield as a YTD basis-point move from its year-start level (`prior_year_end_close`) — a % return on a yield is misleading. ETF rows where the prior-prior year-end close can't be located (e.g. ETF inception after the relevant cutover) render without the period suffix rather than failing
- **Degraded-run banner + coverage-validated batch download (2026-07-08, codex-reviewed 2x).** Yahoo intermittently throttles CI egress (2026-07-07: open screened 64/742, midday 0/742 — hollow digests posted, JP noticed XLV missing from _Sectors_). `batch_download` now measures the fraction of requested tickers with >=1 Close bar, retries (15/45s) below 60% coverage, and returns the best attempt loudly when still degraded (a non-empty PARTIAL batch is the real failure mode — an emptiness check alone never retries). Any run where <50% of tickers returned data renders a `:warning: DEGRADED RUN` banner at the top of the Slack message so a hollow digest can't read as a quiet day.
- Cron schedules use EST-aligned UTC offsets so they always fire after the relevant market event year-round (1 hour late during EDT, but never early)
- `Sigma Watchdog` workflow runs hourly during weekday market hours, detects dropped scheduled runs, and triggers them via `workflow_dispatch`. Posts a Slack heartbeat only when it actually recovers something
- Slack webhooks — stored as GitHub Actions secrets:
  - `SLACK_WEBHOOK` — main sigma-alert channel (`#stock-price-alerts`). Used by the sigma screener for open/midday/close digests
  - `SLACK_STATUS_REPORTS_WEBHOOK` — `#status-reports` channel. Used only by `scripts/weekly_skip_report.py`
