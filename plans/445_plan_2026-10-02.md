# #445 — per-cycle freshness for return_map.html (plan, 2026-10-02)

## Problem
`readable/return_map.html` (runner clone `%LOCALAPPDATA%/sigma-alert-runner/`) is rewritten by
open 09:40, midday 12:35 and close 16:25 ET. `scheduled_jobs_monitor/artifacts.json` declares it
for `SigmaAlert-close` only and records under `_UNCHECKABLE` that declaring it for open/midday
"would let the close run vouch for two dead cycles". The inverse is also live: an open-cycle
write can mask a close that did nothing. mtime of one shared file cannot say WHICH cycle wrote it.

## Facts measured
- CI (sigma-*.yml) never persists `readable/` (gitignored); CI close commits only `cache/*`. So
  the only writer of the runner's `readable/` is the local backstop. CI close cron is 17:30 EDT,
  after the local 16:25, so local close is normally first.
- `local_run.ps1` does `git reset --hard origin/master`; `readable/` is untracked+ignored, so a
  sidecar there survives the reset.
- Screener exits WITHOUT writing the map on: close duplicate-run (`is_duplicate_run`), publish
  gate refusal, return-map coverage gate, write exception. A weekday NYSE holiday lands in a gate.
- Close run takes ~24 min (started 16:25, wrote 16:49 on 2026-10-01); checker already compares
  to the task's LastRunTime with IN_FLIGHT/GRACE.

## Design
1. **Producer (sigma-alert).** New sidecar `readable/return_map.cycles.json`, one entry per mode:
   `{"open": {"ok_at": iso, "last_exit": "written|duplicate|market-closed|publish-gate|coverage-floor|write-failed",
   "last_exit_at": iso, "ref_date": ...}, ...}`. Updated by `return_map.record_cycle(mode, exit, path)`
   at every terminal path of `main()` after the publish decision. `ok_at` advances ONLY on
   `written`, `duplicate` (close: session already published; no rewrite by design, #327) and
   `market-closed` (gate refused AND `not is_nyse_session(today)`). Each mode writes only its own
   key, so no cycle can vouch for another. Read-modify-write; a corrupt/missing file starts from
   `{}`; written via tmp + `os.replace` (falls back to in-place write on PermissionError). Stamp is
   written AFTER the HTML, so a crash mid-write leaves the stamp un-advanced (reads stale = safe
   direction). Failure to stamp is warn-and-proceed, never breaks the alert pipeline.
   `--dry-run` redirects the sidecar path into the state dir like the other writes.
2. **Checker (scheduled_jobs_monitor, own commit).** Artifact pattern grammar gains
   `stamp:<path>#<key>`: `_newest` reads `ok_at` from that key instead of an mtime (expandvars as
   today; unreadable/missing key => no match => `missing`). All existing ran/in-flight/did-not-fire/
   GRACE logic applies unchanged. When stale/missing, the detail appends the stamp's `last_exit`
   + time, so the report says WHY the cycle wrote nothing (the attribution the row asks for).
3. **Declarations.** `SigmaAlert-open/-midday/-close` each -> `stamp:...return_map.cycles.json#<mode>`.
   Remove the open/midday `_UNCHECKABLE` entry; record the reason in the close note.

## Trade-offs / ambiguous calls
- Chose a SIDECAR over an in-HTML `<meta>`: one shared HTML can only carry the LAST writer's
  stamp, i.e. the same one-slot problem. Against: a second file to keep in sync (mitigated by
  writing it after the HTML).
- Chose producer-side `ok_at` (domain knowledge stays in sigma-alert) over teaching the generic
  checker which exits are benign.
- `duplicate` and `market-closed` count as OK. Against: a duplicate close leaves the local HTML
  at the midday data; that is #327's existing decision, not changed here.
- Until each cycle first runs on the new code (09:40 today), its key is absent => `missing` for
  open/midday/close on this morning's 08:45 check. Mitigation: seed the runner's sidecar once by
  hand? NO - that would be a fabricated stamp. Accept one morning of `missing`, OR deploy the
  checker change after the first cycles have written. Decision: commit both; state the transition.

## Verify
- Unit tests both repos (record_cycle round-trip/corrupt/other-keys-preserved; main() exit paths
  stamp; checker stamp parse, missing key, stale with last_exit in detail, per-cycle independence).
- Dry-run screener `--mode close --dry-run` and confirm the sidecar lands in the state dir only.
- `python artifact_freshness.py --dry-run` against the real runner clone.
